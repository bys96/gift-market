# 하이브리드 검색 운영 준비

현재 구현은 소규모 데이터 검증용이다. `SEARCH_SEMANTIC_ENABLED`와
`SEARCH_REINDEX_ENABLED`의 기본값은 모두 false다. 운영 적용 전 실제 MySQL에서
수동 DDL과 결과 품질, CPU·메모리 및 응답시간을 검증한다.

`docs/sql/product-embeddings.sql`은 자동 마이그레이션이 아니다. 벡터는 Java
`ByteBuffer` 기본 빅엔디언 float32 배열이다. 모델·차원·상품을 기본 키로 관리한다.

DDL 준비 후 두 플래그와 Gemini 키를 설정하고 관리자 권한으로
`POST /api/admin/product-search/reindex?afterId=0&limit=1`을 호출한다. 반환된
`nextCursor`를 다음 `afterId`로 사용한다. `MORE`는 다음 배치가 필요하며
`RETRY`는 같은 `nextCursor`로 재호출한다. `COMPLETE`는 끝을 뜻한다. 최대
배치 크기는 10이고 호출 간격 제한으로 `RETRY`가 발생할 수 있다. 재색인은
자동 스케줄되지 않는다. 작업 후 재색인 플래그를 끈다.

검색은 전체 필터 후보가 `SEARCH_MAX_CANDIDATES` 이내이고 모든 후보의 현재
모델·차원 벡터가 준비된 경우에만 시도한다. 상한의 최대값은 100이다. 그렇지
않거나 API/테이블 오류가 나면 기존 SQL로 돌아간다. 명시한 최신순·가격순·인기순은
유지한다. 검색어가 있고 sort를 생략하면 정확 일치, 부분 일치, 띄어쓰기·오타,
의미 유사도 순으로 정렬하며 동점은 기존 최신순을 유지한다.

상품 버전과 상품명·설명·카테고리·활성 선물 상황을 포함한 입력 해시를 검색 시
확인한다. 불일치가 있으면 SQL로 폴백하며 관리자가 재색인해야 한다. 여러 프로세스의
재색인은 상품 행 잠금과 기본 키로 저장을 직렬화하지만 중복 외부 호출은 가능하다.
자동 재색인은 제공하지 않는다. 모델이나 차원 변경 시 해당 조합을 다시 색인한다.
모델 변경 전 선택한 모델의 검색 task type 지원 여부를 확인해야 한다.
